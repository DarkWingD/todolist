What the numbers point at

  1. 1The rail stays put. It already exists in AppShell on desktop. Nothing changes here.
  2. 2Index column, 296px, scrolls on its own. Rows replace the cards: emoji tile, name, one line of context, and the open count on the right where the eye can run down it. Groups are Built in, Your lists, Kids. The selected row uses the same accent-soft treatment the rail uses.
  3. 3Search moves into the index and filters it live, since on a phone it already lives on the Lists tab. Typing / anywhere focuses it.
  4. 4Detail pane, capped at 760px. Same list screen as the phone, with the back arrow gone. Due date and assignee sit inline on the row instead of a second line, because there is room. Shopping spreads its meal headings over two columns.
  5. 5Task details slide in from the right instead of replacing the screen. The list stays visible so you can work down it: click a task, edit, click the next. Escape closes it.

Behaviour

Remember the last open list. Coming back to Lists lands you where you were. First visit opens the first list in "Your lists", never an empty pane.

Below about 900px wide the index and detail stack back into the phone flow that already works. Nothing is redesigned for the phone.

Keyboard: ↑ ↓ move between lists, N focuses add, / focuses search, Esc closes the inspector. Cheap to add once panes exist.

The + in the rail adds a task to the open list, matching what the floating + does on the phone. "New list" lives at the foot of the index where lists are.

Same shape, other tabs

Today could split the same way: agenda on the left, the selected task's details on the right. Cal and Meals already run full width and stay as they are. You is a settings page and reads fine in a column.

Mockup only. Data is made up. The child list (Bertie, Maisie) shows where it would open, not a redesign of that screen. Colours and type are the app's Nudge theme tokens, so the other two themes would follow automatically.
